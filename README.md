# Welcome to the inno.space Website Repository

## Running the Website locally

To run the website locally, you can refer to the [Jekyll Quickstart Guide](https://jekyllrb.com/docs/). Here are some important notes:

- You will need Ruby version 2.7.0 or higher to run the website. Macbooks come with a preinstalled version of Ruby, but this one is outdated and cannot/should not be used. You will have to install a newer version of Ruby via a version manager, which allows you to switch between the two Ruby versions as needed. Jekyll recommends using [chruby](https://github.com/postmodern/chruby)
- Before you compile the website, update your .gitignore to look something like this:

```gitignore
_site
.sass-cache
.jekyll-cache
.gitignore

_site/
.sass-cache/
.jekyll-cache/
.jekyll-metadata

# Ignore folders generated by Bundler
.bundle/
vendor/

# For Mac users, ignore generated ds_store files 
.DS_Store
*/.DS_Store
```

- Once you have followed the instructions from the quickstart (installing bundler with `gem install jekyll bundler`), you can switch to the Ruby you have installed and compile the website:

```bash
chruby 4.0.0 #or whichever version you have installed
bundle exec jekyll serve
```

- Sometimes, gems will need to be updated to newer versions. You can update all gems in the project (specified in the `gemfile`) with `bundle update` and then run `bundle install` again to test locally if they still interact correctly

## Tech Stack

The website uses a few technologies/libraries/components for different features:

- HTML, JavaScript and CSS/SCSS
- Markdown to allow for easy construction of news posts and past project showcases 
- The [Liquid](https://shopify.dev/docs/api/liquid#liquid-basics) template language to provide basic functionality for variables and loops
- YAML file structure to capture structured information which can be used with Liquid functionality
- [Jekyll](https://jekyllrb.com/docs) to generate a **static** website from all the tech contents mentioned above
  - Jekyll runs on **Ruby**, so ruby is required to compile the website locally
- Github pages for hosting (*"GitHub Pages is powered by Jekyll", so this is a good pairing*)

In addition to the basic functionality for generating a static website, the following libraries/functionalities are used:

- [Panellum](https://pannellum.org) is used for showing the panorama of the maker.space 
- Fontawesome icons are used across the website 


## The Template

- The inno.space website is based on a template created with Jekyll
  - This template can no longer be accessed, so its base structure is stored in the repository in case its contents are needed in the future
- The template consists of a wealth of CSS which create a consistent design for components used on the website
- `theme`, `_posts`, `images/@stock` as well as some content in the `_includes` folder (`services.html` and `sidebar.html`) all belong to the original website template, and display the functions and features of the website offerd by the template
  - The HTML layouts in the `_includes` folder have been left there so they can be easily used in the future, the rest of them theme has been moved into its own folder so that it cannot be accessed in the compiled website


## Naming Conventions

- Folders starting with "_" indicate to Jekyll that their contents should not be copied into the generated website. This includes folders containing the Markdown base for e.g. project pages
- Subfolders in the "images" folder are prefixed with an "@". This does not have any specific connotations for the compilation of the website via Jekyll
- **Underscores are not allowed when creating markdown files** for projects/news/etc., as this leads to the file not being compiled

## Folder Structure

The structure of the website follows the directory structure as [recommended by Jekyll](https://jekyllrb.com/docs/structure/).

- `_news` and `_projects` contain markdown files for news articles and past student projects in markdown format. The markdown files are 
- `_includes` contains HTML elements that can be inserted into other pages of the website, e.g. the header and footer
- `_layouts` contains HTML to render the content of markdown files, e.g. for news posts and student project pages
- `_data` contains separate YML files with structured information (e.g. about the machines in maker.space), which can be accessed from the HTML pages
  - YML can also be included directly into the HTML pages

### Content for E-Mail

- The folder `mail` contains images that can be inserted into the HTML-formatted emails sent out to students, e.g. for course advertising. It is not used in the website directly, but needs to remain there so that the images can be referenced
- Similarly, the folder `inactive_pages` contains several pages that can be linked to in emails, which contain e.g. course overviews for students of different faculties, information on how to apply to courses and information for potential sponsors
  - These pages are currently not up to date, and inacessible due to their location, but they can be reactivated by moving them back to the top folder structure. Before doing so, they ought to be updated with the current information on courses

# Adding Content to the Website

## Adding Student Projects

- Student projects information is added in markdown format into the folder `_projects`
- Each project needs at least:
  - One thumbnail for the "Past Projects" section
  - One image to display in the project subsite
  - A (short) text describing the project
- Existing markdown files can be used as templates on how to format the information
  - In the yml information at the top of each file, `title`, `year`, `program` and `sponsor` have to be provided
  - At least one image has to be provided in the `image` list

Here is a short description of the process for adding new projects:

1. Copy one of the markdown files in the `_projects` folder
2. Change the heading (prefixed with `###`) and description to fit the new project
3. Change the `title`, `year`, `program` and `sponsor` fields in the yml at the top of the markdown file
4. Add the images you want to display for the project to the folder `/images/@projects/`
   1. Name the images in a way that connects them to the project and number them (e.g. <project_name>1.png or <team_name>1.png)
   2. Replace the image paths from the base markdown file you copied from with paths leading to the images for the new project you just uploaded
5. Add a thumbnail for the project, also to the `/images/@projects/` folder
   1. The image format must be square
   2. Use the same naming convention you used for the other images, but add the suffix "_thumbnail" (e.g. <project_name>_thumbnail.png)
6. In the HTML file `projects.html`, add information about the project in the same way the other projects are referenced in the list "works", **at the top of the list**
   1. Here, add the path to the thumbnail, so that this image will be displayed in the overview of past projects

The HTML layout file `collection.html` will be automatically used to format the contents from the markdown file into a project page. 

## Adding News Articles

- Like student projects, news articles are added as markdown files, to the folder `_news`
- Each news article needs at least:
  - One thumbnail for the "News" section
  - A title, subtitle and text describing the news, as well as a date to attach to the news article
- Existing markdown files can be used as templates on how to format the information
  - In the yml information at the top of each file, `title`, `subtitle`, and `date` have to be provided
  - One image has to be provided in the `image` list
    - This image can differ from the news post's thumbnail, but does not have to

> **Important**: If there is a social media post/website/etc. about the news article already, you do not necessarily need to
> create a markdown file for the article, however, you still need a thumbnail. Instead of linking to a markdown file in the 
> `_data/news.yml` file, simply insert the link to the social media post/website/etc.

Here is a short description of the process for adding new news articles:

1. Copy one of the markdown files in the `_news` folder
2. Change the text of the news article, and add formatting (headings, bold, links, etc.) if you want
3. Change the `title`, `subtitle`, and `date` fields in the yml at the top of the markdown file
4. Add the image you want to display for the project to the folder `/images/@news/`
   1. Name the image in a way that connects them to the news post (e.g. <news_post_title>.png)
   2. Replace the image path from the base markdown file you copied from with path leading to the image for the new news article you just uploaded
5. Either add a separate thumbnail for the news article, also to the `/images/@news/` folder, or use the same image
6. In the YML file `_data/news.yml`, add information about the news article in the same way the other news articles are referenced **above previous articles**. A more detailled tutorial is provided in the comments above the yml content

# Small tips for Bug catching

- When using liquid to iterate over files in a folder, e.g. when calling the `image-gallery` layout via `{% include image-gallery.html folder="/images/@room" %}`, it's interesting to note that the folder path does not just take all files in the folder "room", it takes all files in *all* folders starting with "room"
  - This was discovered when the exact snippet somehow rendered all images from the folder "room360" into the image gallery as well
